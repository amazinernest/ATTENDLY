# ClassMark — Production University Lecturer Attendance Management Platform

ClassMark is a production-ready, full-stack academic web application engineered for university lecturers in Nigerian universities, polytechnics, colleges of education, and tertiary institutions to import student rosters, conduct fraud-resistant in-class QR attendance sessions, track semester attendance percentages, and generate official Excel and PDF semester reports.

---

## 1. System Architecture & Tech Stack

- **Framework**: Next.js 16 (App Router) with TypeScript (Strict mode)
- **Styling**: Tailwind CSS v4 with bespoke Academic Slate & Navy Design System
- **Database & ORM**: PostgreSQL 16 with Prisma ORM 7 & `@prisma/adapter-pg` driver adapter
- **Authentication**: Modern HttpOnly, Secure, SameSite JWT session cookies, password hashing with bcrypt, single-use email verification tokens, and password reset workflows
- **QR Code Engine**: High-resolution SVG & Data URL generation (`qrcode`)
- **Document & Spreadsheet Importers**:
  - Excel (`.xlsx`, `.xls` via `xlsx`, preserving leading zeros)
  - CSV (`.csv` with delimiter and quote handling)
  - Word (`.docx` table and text extraction via `mammoth`)
  - PDF (`.pdf` selectable text parser via `pdf-parse`)
- **Export Engines**:
  - Excel (`.xlsx` multi-sheet workbooks with formula-injection neutralization via `exceljs`)
  - PDF (`.pdf` academic formatted documents with repeating headers and page numbers via `jspdf` & `jspdf-autotable`)
- **Testing**: Automated test suite (`vitest`) with PostgreSQL integration tests

## 2. Relational Database Schema

The database is built on PostgreSQL with strict foreign keys, composite unique constraints, and audit logging:

1. **`User` (Lecturers)**: Stores credentials (`passwordHash`), institutional email, full name, institution, department, verified status, time zone (`Africa/Lagos`), default threshold (`75.0%`), and default session duration.
2. **`Course`**: Represents academic courses (`code`, `title`, `session` e.g. `2026/2027`, `semester`, `attendanceThreshold`, `status: ACTIVE | ARCHIVED`). Unique composite constraint: `[lecturerId, code, session, semester]`.
3. **`Student`**: University student identity (`matricNumber` unique primary text identifier, `fullName`, `email`, `department`, `level`, `studentPin`).
4. **`CourseEnrolment`**: Junction table binding students to courses with `status: ACTIVE | WITHDRAWN`. Unique composite: `[courseId, studentId]`.
5. **`AttendanceSession`**: Active and completed lecture sessions (`token` cryptographic public URL, `sessionPin` in-class 4-digit code, `status: OPEN | CLOSED`, `startTime`, `expiresAt`, `verificationMethod: STUDENT_PIN | EMAIL_OTP | OPEN_CHECKIN`).
6. **`AttendanceRecord`**: Individual student attendance events (`status: PRESENT | ABSENT | EXCUSED | LATE`, `checkInTime`, `isManualOverride`, `overrideReason`, `overrideByLecturerId`). Unique composite: `[sessionId, enrolmentId]` preventing race-condition duplicate check-ins.
7. **`StudentVerificationOTP`**: Single-use, expiring passcodes for student institutional email verification.
8. **`AuditLog`**: Tamper-evident ledger of administrative actions, roster imports, session closures, and manual attendance overrides.

## 3. Strict Multi-Lecturer Tenant Isolation

Every query and mutation enforces tenant ownership at the application and database level:
- Lecturer A can never view or manipulate Lecturer B's courses, student rosters, attendance sessions, or semester reports.
- Tampering with course or session IDs in URLs or API calls immediately returns `404 Not Found` or `401 Unauthorized`.
- Public attendance check-in routes (`/attendance/[token]`) expose only course code, title, and session status, completely hiding the full class list, enrolled student names, or student rosters.

---

## 4. Student Identity & Anti-Impersonation Workflow

To prevent proxy attendance (students marking on behalf of absent friends):

1. **Unique Cryptographic Session Link**: Each lecture attendance session generates an unpredictable token (`crypto.randomBytes(24)`).
2. **In-Class Projected PIN**: A prominent 4-digit code is projected on the lecture screen. Students must enter this code to submit attendance.
3. **Identity Verification Options**:
   - **Student PIN**: Individual student PIN entered alongside the matriculation number.
   - **Institutional Email OTP**: Single-use 6-digit passcode dispatched to the student's registered institutional inbox, expiring in 10 minutes.
   - **In-Class PIN Only**: Quick check-in requiring the projected classroom PIN.
4. **Authoritative Server Timestamps**: Timestamps are generated by the PostgreSQL server, not client devices.
5. **Single Check-In Guarantee**: Database-level unique constraint prevents multiple records for the same student in a session.
6. **Auditable Manual Overrides**: For students without mobile devices or legitimate medical excuses, lecturers can manually record attendance with a mandatory reason, automatically logging an audit entry.

## 5. Attendance Calculations & Semester Formulas

- **Student Attendance Rate**:
  $$\text{Attendance \%} = \left(\frac{\text{Eligible Sessions Attended}}{\text{Total Eligible Sessions}}\right) \times 100$$
- **Zero-Session Handling**: When no completed sessions exist, the system safely renders `N/A` without dividing by zero.
- **Threshold Classifications**:
  - $\ge 90\%$: Excellent
  - $75\% - 89.9\%$: Good (Qualified)
  - $60\% - 74.9\%$: Fair
  - $< 60\%$: Low Attendance (Deficient)
- **Exam Eligibility**: Configurable course benchmark (default 75%). Students below the threshold are flagged in the dashboard, roster, and export reports.

## 6. Local Development Setup

### Prerequisites
- Node.js v20+ (Node v26 supported)
- PostgreSQL 14+ (e.g. Homebrew PostgreSQL or Docker)

### Step 1: Install Dependencies
```bash
npm install --legacy-peer-deps
```

### Step 2: Configure Environment
Copy `.env.example` to `.env`:
```bash
cp .env.example .env
```
Ensure your `DATABASE_URL` points to your PostgreSQL instance:
```env
DATABASE_URL="postgresql://mac@localhost:5432/classmark?schema=public"
SESSION_SECRET="your-strong-random-32-character-session-secret"
NEXT_PUBLIC_APP_URL="http://localhost:3000"
NODE_ENV="development"
```

### Step 3: Run Database Migrations
```bash
npx prisma migrate dev --name init
npx prisma generate
```

### Step 4: Run Automated Tests
```bash
npx vitest run
```

### Step 5: Start Local Development Server
```bash
npm run dev
```
Open [http://localhost:3000](http://localhost:3000) in your browser.

---

## 7. Production Deployment Instructions

1. **Managed PostgreSQL**: Provision a PostgreSQL database (e.g. AWS RDS, Neon, Supabase, Railway).
2. **Set Environment Variables**:
   - `DATABASE_URL`: Production PostgreSQL connection string.
   - `SESSION_SECRET`: Cryptographically random 32+ character key.
   - `NEXT_PUBLIC_APP_URL`: Your production domain (e.g., `https://classmark.youruniversity.edu.ng`).
   - `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `EMAIL_FROM`: Transactional SMTP credentials.
3. **Run Production Migrations**:
   ```bash
   npx prisma migrate deploy
   ```
4. **Compile Production Bundle**:
   ```bash
   npm run build
   ```
5. **Start Application Server**:
   ```bash
   npm start
   ```
